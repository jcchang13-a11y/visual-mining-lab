# 施工斷面｜30390 公式改線後的混合狀態

狀態：保留／未閉合

這個斷面記錄第十七分單元 `30390` 在公式標準化之後留下的「新接口包住舊工作語言」狀態。這不是現在要清掉的髒資料，而是一個很清楚的施工剖面。

## 初始封存斷面

基準節點：`fa5fe86379f3ef74934b4160f8fd2f0f68e44174`

當時單元開頭 PLS 使用：

> P：「者」呼叫占據位置／「S / S = S barred」

正文後段也直接寫：

> 它被放入「S / S = S barred」公式：「一切法」/ 一切法 = 一切法 barred。

以及：

> 放進公式：「一切法」/ 一切法 = 一切法 barred。

這一組寫法很明顯是施工中的工作語言：英文 `barred`、斜線、等號、引號全部混在一起，還沒有收斂成後來的正式 glyph。

## 現行斷面

目前 `main` 的同一單元，PLS 已改成：

> P：「者」呼叫占據位置／「{{S}}」

但正文兩處仍保留：

> 「一切法」/ 一切法 = 一切法 barred

也就是說，公式標準化只把一部分入口改成 `{{S}}`，舊工作記號並沒有從整個單元完全消失。

## 判定

不再把這種混合狀態視為「尚未清乾淨」。恰恰相反，它適合第八版：

- `{{S}}` 是後來建立的正式渲染接口。
- `S / S = S barred` 是更早的施工語言。
- 同一單元兩者並存，顯示公式系統不是一次完成，而是邊蓋邊換管線。

正式規格仍是：基本式 `S = ～S`；名稱層次由 `{{S}}` 生成上層 `S`、下層 `～S` 的直式公式。

但 30390 目前不做「徹底清理」。舊的 `barred` 語言留在正文，作為這次公式改線留下的裸露接頭。

## 未決

後續若要處理 30390，不問「哪個才是正確格式」，而問：

1. 哪些舊工作記號應直接留在正文；
2. 哪些應移到施工斷面但保留原位置的接口；
3. 哪些混合狀態反而最能讓人看見這套公式怎麼長出來。

目前暫採：**不修。讓它露著。**
