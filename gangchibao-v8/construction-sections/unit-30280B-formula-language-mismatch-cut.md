# 30280B｜公式換線後，說明文字沒有一起換

> 施工斷面：第十分前段〈莊嚴佛土者，即非莊嚴，是名莊嚴〉。

這個單元保存了一個很適合「爛尾樓版」的事故：**公式的視覺管線已經換成 `～`，但旁邊解釋舊字形的施工語言還留著。**

## 初始封存斷面

基準：`fa5fe86379f3ef74934b4160f8fd2f0f68e44174`

當時公式寫成：

```text
「莊嚴」
──────────
 莊嚴 = 莊̸嚴̸
```

正文接著解釋：

> 「這個斜槓不是把莊嚴取消，而是把『莊嚴＝莊嚴』這個自我穩定的關係劃開。」

所以在原始施工面裡，「斜槓」與刪線字形彼此對得上。

## 現行斷面

公式標準化後，公式已改成：

```text
「莊嚴」
──────────
 莊嚴 = ～莊嚴
```

但緊接著的說明仍然是：

> 「這個斜槓不是把莊嚴取消……」

現在畫面上已經沒有那個斜槓。換句話說，renderer／公式規格已經改線，舊的解釋管線卻還從牆裡伸出來。

## 暫採施工判定

**不修。**

這不是單純的錯字，而是公式標準化留下的語義錯位：

```text
舊施工語法：刪線字形 ──→ 「這個斜槓」
                         │
                         ×  標準化施工切斷
                         │
現行正式規格：～S ──────┘
```

若把「這個斜槓」改成「這個波浪號／否定記號」，讀起來會更乾淨，但也會把一次真實的返工痕跡抹掉。爛尾樓版反而應讓兩個年代的管線同時露在牆外。

因此此處採雙層身份：

- 正式公式規格仍是 `S = ～S`。
- 「這個斜槓」保留為舊刪線公式的語言化殘留。
- 不把兩者強行統一。

## 與其他斷面的關係

30260B 已保存「刪線式 → `～`」的公式改線；30390 保存新 renderer 與舊 `barred` 工作語言並存。30280B 更進一步顯示：**即使字形已被成功替換，描述字形的自然語言仍可能留在上一個施工年代。**

這使公式標準化不再只是兩個 glyph 的比較，而形成三層施工史：

```text
字形層：莊̸嚴̸  →  ～莊嚴
語言層：「斜槓」 ───────── 留存
規格層：S = ～S ───────── 現行
```

三層沒有完全同步，正是此斷面的內容。
