# 30320 施工斷面｜名字公式從裸露工作記號換成 renderer

這份斷面保留第十三分後半 `unit-30320.md` 的公式換線，不把後來的 renderer 當成單純排版升級。

## 初始封存斷面

在 V8 初始封存節點 `fa5fe86379f3ef74934b4160f8fd2f0f68e44174`，正文直接裸寫工作公式：

```text
"S" / S = S barred
```

套到本節時又裸寫：

```text
"般若波羅蜜" / 般若波羅蜜 = 般若波羅蜜 barred
```

這一層的工作語言很粗：名字放在上面，下面是「S = S barred」。它還沒有被包成正式視覺元件。

## 現行接口

後續公式 renderer 接入後，上述兩處分別改成：

```text
{{S}}
```

與：

```text
{{般若波羅蜜}}
```

正文因此把公式交給 reader 的視覺元件處理，而不是在 Markdown 裡直接裸露施工公式。

## 沒有一起換掉的舊管線

接口雖然換了，緊接著的文字仍保留舊工作語言：

- 「下面是這個名字成立的條件：S 不是完整、自足、無裂縫的 S，而是 S barred。」
- 「所謂般若波羅蜜……是帶著『即非』的裂縫而成立的名字。」

也就是說，畫面上的正式接口已經換成 renderer，但理論解說仍看得見 `S barred` 這一代施工語彙。

這裡暫不清理。若把 `S barred` 全部改寫成現行 `S = ～S` 的統一語言，會抹掉公式曾經如何被理解、如何被視覺化、又如何換線的歷史。

## 現行判定

- 正式規格仍是 `S = ～S` 與名稱層次直式公式。
- `{{S}}`／`{{般若波羅蜜}}` 是現行 renderer 接口。
- `S barred` 保留為舊工作語言與施工斷面，不重新取得正式規格地位。
- 本單元不修順這個接口錯位。

這個斷面與 `30310B` 類似，但位置更關鍵：30320 正在直接解釋「是名」如何成立，因此公式視覺語法的換線本身也進入了它所談的問題——名字／接口可以換，底下的裂縫沒有因此消失。
