# 第八版公式巡檢斷面｜2026-09-14｜LIVE51

> 不清場，只加鷹架。這不是「統一公式」提交，而是把現行接口與歷史施工線同時標清，避免後續施工把舊公式誤判成待清理錯誤。

## 現行正式接口

目前 LIVE reader 的 `formula-scaffold.js` 已把正式顯示固定為：

- 中文讀法：`S 即非 S，是名 S`
- 符號接口：`"S"/~S`
- `{{S}}`／`{{名稱}}` 交由 renderer 生成現行正式顯示。

`formula-scaffold.js` 明確不再偷偷改寫正文裡的 `S = ～S`、`X = ～X`、刪線式、`S barred`、`S ≠ S` 等舊施工語。

## 歷史公式不得清場

施工簿與各單元仍保留多套舊公式／舊解說：

- `S = ～S`
- `福德 = 福̸德̸`、`佛法 = 佛̸法̸`
- `S barred`
- `S ≠ S`
- 「斜槓劃開」等已與現行 renderer 不完全一致的工作語

這些現在一律視為歷史斷面，而不是正文錯字。後續巡檢若遇到它們，只確認其閱讀層身份，不做全書替換。

## 本輪判定

1. `formula-scaffold.js` 的現行接口與 LIVE footer 一致，無需改寫。
2. `construction-ledger.md` 早期「正式規格目前採 S = ～S」的句子與現行接口不同，但它本身已成為施工史；本輪不覆寫，另以本斷面補充現況。
3. 回溯圖 caption、P/L/S/N/F、WORK note、舊 reader 原件若出現舊公式，不納入自動正規化。
4. 後續若真的發現正文把歷史公式誤當現行教學公式，優先加閱讀層／註記鷹架，不直接清洗原文。

## 巡檢原則

公式不是把全書抹成同一種字形，而是分清：

- 現行可運作接口；
- 歷史施工公式；
- 工作語殘留；
- 真正會誤導閱讀層的錯位。

只有第四類才需要施工修補；前三類繼續留在樓裡。
