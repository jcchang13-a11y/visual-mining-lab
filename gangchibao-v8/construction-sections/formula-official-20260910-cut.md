# 公式正式規格改線斷面｜2026-09-10

這不是清場，也不是把舊公式全部改掉。這一張斷面只標示「現在正式對外運作的公式」與「施工史裡仍保留的舊管線」之間的分界。

## 現行正式規格

中文正式寫法：

`S 即非 S，是名 S`

符號正式寫法：

`"S"/~S`

其中：

- `"S"` = 「是名 S」
- `~S` = 「即非 S」
- 讀法不是 `S` 對抗 `~S`，也不是把兩邊重新做成兩個死實體。
- `~S` 是基礎：只有先承認 S 不是一個固定、自性成立的死實體，才可以說 `"S"`，也就是「是名 S」。
- 引號不是裝飾；它標出「是名」這個層次。

## 現行 runtime 鷹架

`formula-scaffold.js` 已以 `"S"/~S` 為正式輸出，並把 `{{...}}` renderer 產生的公式、獨立成行的舊基本式與未標明為歷史施工的舊變體，轉成同一正式格式。

明確位於 `WORK`／施工史／舊公式說明中的舊寫法不清除。

這符合本版規則：**正式規格只有一套；歷史施工痕跡可以有很多套。**

## 已知仍裸露的舊管線

施工簿與既有事故斷面仍可見下列歷史規格：

- `S = ～S`
- `S = ~S`
- 刪線字形
- `S barred`
- `S ≠ S`
- 早期分數／renderer 工作接口

這些不再是正式規格，但不因本次改線而刪除。只要它們的語境是在說明「以前怎麼蓋」，就保留。

## 一個目前可見的接口錯位

`reader-core.html` 原始 footer 仍裸寫「基本式固定為 S = ～S，名稱層次以 {{S}} 生成直式公式」。目前 `formula-scaffold.js` 在 runtime 會把這一段改成正式規格，因此讀者層不再以舊式作現行規則；但 source 裡的舊 footer 暫時不整棟重寫，避免為改一行而覆蓋其他施工。

這個位置先標記為：

`FORMULA SOURCE INTERFACE / runtime 已改線；source 尚留舊管線`

後續如果能在不覆蓋其他修改的條件下安全做 source-level 單點更新，再把 footer 的「現行規格」文字換線；施工簿裡關於 `S = ～S` 的歷史紀錄仍保留。

## 巡檢原則

1. 正文／公式框／圖說／同心圓圖／SVG／閱讀層／PDF／出版層，只要是在聲稱「現在公式是什麼」，統一用 `"S"/~S`。
2. 中文解說若是正式定義，統一用 `S 即非 S，是名 S`。
3. 舊公式只在能辨識為歷史施工、WORK、返工斷面或明確引述舊規格時保留。
4. 不把 `S = ～S`、`S = ~S`、`S barred`、`S ≠ S` 重新解釋成現行公式。
5. 第二層「非 S，亦非非 S」的符號寫法尚未封定；在未封定前不自行發明。

## 狀態

這一斷面不是封版標記。它只把 2026-09-10 之後的正式公式施工基準釘在牆上，供後續逐單元巡檢時比對。
