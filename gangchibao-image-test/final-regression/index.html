A｜站內 SVG（相對路徑）

這一頁故意把前九輪的關鍵條件放回同一個長頁面裡。圖片不是正文的前置條件；任何一張圖失敗，文字都必須繼續。手機版維持單欄自然流動，不使用裁切式 object-fit，不讓圖片造成水平溢出，也不讓固定高度卡住閱讀。

這段是長文滾動測試。真正接入《剛吃飽》時，圖片可能出現在章首、段落之間、公式之後或章尾。裝配機制必須把圖視為可失敗的獨立元件，而不是讓正文依賴某個外部圖床、某個暫時網址或某次快取狀態。

B｜真實 PNG（站點根路徑）

PNG 用來確認真正點陣資產能從同一 GitHub Pages 專案穩定載入。這裡刻意使用站點根路徑，與上面的相對路徑形成對照；未來即使閱讀器搬進較深的目錄，站點根路徑仍不應因頁面深度而失效。

C｜快取目標（同名檔＋版本參數）

快取測試沿用同名檔案，以版本參數明確要求新資產。這不是要求瀏覽器完全不用快取，而是要求部署後有可靠方式讓新版資產被取得，避免讀者長期卡在舊圖。

D｜真實 JPG（跨資料夾相對路徑）

這張 JPG 從另一個專案資料夾載入，用來確認不同路徑層級仍可以在正常文件流中顯示。頁面本身位於 gangchibao-image-test/final-regression/，因此它也同時是一個較深層頁面的路徑測試。

E｜故障圖 fallback

長頁面的後段仍然必須可以正常捲動。文字尺寸、行距與圖片寬度都只依容器寬度收縮，不應出現兩欄擠壓、圖片裁切、文字壓在圖上或因圖片尺寸造成整頁橫向捲動。
